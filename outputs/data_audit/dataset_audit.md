## 4. Duplicates

- Exact (SHA-256) duplicate pairs among canonical images: 4 (0 across patients).
- Perceptual-hash candidates (pHash Hamming ≤ 6): 3650 pairs; 127 within-patient, 3527 cross-patient.
- Confirmed visual duplicates (pHash candidate and central high-pass texture correlation ≥ 0.9): 9 pairs, of which 0 cross-patient.
- Patients merged into a shared split group because of cross-patient duplicates: 0 (0 groups). Splits keep each group in one partition (`patient_groups.csv`).

pHash alone is not discriminative on these images (smooth mucosa, shared octagonal mask): most cross-patient candidates are different scenes with similar composition, which the texture correlation rejects (cross-patient maximum is listed in `duplicate_report.csv`).

Within-patient near-duplicates are expected (consecutive captures) and cannot leak because all of a patient's images share one partition.

### Interpretation

- `Presence_of_atrophy` and `Gastritis_type` are exact functions of `Distribution_of_atrophy` in all 229 patients. The independent label set is {H. pylori status, atrophy distribution}; the other two tasks are mathematically redundant given the distribution label and must not be reported as independent clinical findings.
- H. pylori status is **not** a function of any other label. The observed cell `corpus_predominant × positive = 0` is an empirical association (consistent with autoimmune type A gastritis), not a definitional rule; it is **not** hard-coded into any model.
- The deterministic mapping used by the structured head is re-derived from the *training* patients of each split and verified there (`src/models/structured_head.py`); this descriptive audit does not feed model selection.

## 6. Published split

The EGID paper (Li et al., Sci Data 13:1396, 2026) reports a patient-level multi-label stratified split of 161/34/34 patients (4,065/853/965 images) and per-cohort class counts (its Table 3) but does **not** publish the patient IDs, the seed or the splitting code. The split therefore cannot be reconstructed. `scripts/prepare_data.py` creates a split with the same cohort sizes and the same per-cohort class counts (where achievable); published metrics are **not directly comparable** with ours.
